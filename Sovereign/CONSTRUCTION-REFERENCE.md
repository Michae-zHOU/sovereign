# 建造系统：Victoria 3 对照与本轮实现边界

核查日期：2026 年 9 月 19 日。参考包括 Paradox 官方开发日志，以及本机安装的 **Victoria 3 1.13.11（Matcha）**公开游戏配置。以下是机制研究和本项目的独立实现说明，没有复制原游戏的源码、界面文件或美术资源。

## 为什么旧版建造不对

旧版 `Simulation/SimulationEngine.cs` 的 `BuildFor` 在下单时一次性扣除全部金币、木材和工具，再给项目设置固定天数。`TickConstruction` 每天让每座城市的第一项工程分别减一天。因此增加施工城市就能增加并行速度，而国家既没有营建产业，也没有统一的施工能力约束。

这直接导致三个问题：施工速度与营建能力、持续预算没有关系；材料涨价与施工中的项目没有关系；“每城 5 项、全国 20 项”混淆了待办清单长度与真实施工能力。仅改变按钮颜色和面板位置，解决不了这些机制差异。

## 官方机制与版本区别

### 全国建造能力与施工支出

建造能力是全国每周可投入的施工点数。营建部门雇佣人口、使用材料和生产方式产生额外建造力；国家另有少量基础能力，避免没有营建部门就永远无法建设的循环。工程按全国队列顺序取得能力，单项有进度上限，剩余能力流向后续工程。每项工程扩建的是特定州内某类建筑的一个等级。

材料是施工期间的持续支出，利用率下降时材料需求相应下降；部门的在职人员仍需工资。地区建设效率影响投入转化为进度的比例，地形、市场接入和当地营建部门都可能影响效率。开发日志使用的“每周上限 50”等数字只是演示，不能当成发行版常量。[Paradox 官方开发日志 #36：Construction，2022-03-03](https://store.steampowered.com/news/posts/?enddate=1646329240&feed=steam_community_announcements)

### 私人投资不是政府队列的另一个名称

1.2 引入私人自动投资队列。经济法决定政府与私人对建造能力的分配；某一方用不完的能力可让另一方使用。私人项目由投资者决定，玩家不能像政府工程一样直接排序或取消。[官方开发日志 #71，2023-01-18](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-71-autonomous-investment-in-1-2)

1.7 又改变了建筑等级的所有权、金融区和庄园、私有化及外国投资，并取消了旧的“直接控制投资池”规则。不能把较早版本的可选规则描述成当前版本完整机制。[官方开发日志 #110，2024-03-28](https://forum.paradoxplaza.com/forum/developer-diary/victoria-3-dev-diary-110-building-ownership-foreign-investment.1647879/)

### 选址信息是操作流程的一部分

原作的建造交互同时展示基础设施、可用劳工和资质，并允许从选址列表进入相关建筑详情。玩家需要比较地点，再把工程加入队列；一个默认把产业建到首都的购买按钮不能替代这个流程。[官方开发日志 #74：UX Improvements，2023-02-08](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-74-ux-improvements)

## 可独立实现的数学模型

设 `C` 为全国本周建造力，`P[i]` 为项目已完成点数，`R[i]` 为所需点数，`E[i]` 为地区效率，`M[i]` 为单项每周实际进度上限。按队列顺序计算：

```text
投入[i] = min(剩余全国建造力, M[i] / E[i], (R[i] - P[i]) / E[i])
进度[i] = 投入[i] × E[i]
剩余全国建造力 -= 投入[i]
```

这个模型区分“消耗的全国点数”和“工程得到的进度”。效率提高会减少完成同样工程占用的能力。地区、科技和公司修正如何组合、边界条件怎样结算，仍需按选定目标版本逐项验证；上述是明确、可测试的独立实现模型，不是声称取得了原作内部 C++ 算法。

当前引擎按天运行，使用周等价值展示：每日上限是周上限除以 7，完成日仅消耗剩余点数，余量可给后项。排队长度不参与计算产能。全国暂停和单项暂停都保留工程进度；取消不会退回已经投入的材料。

## 本轮代码实际实现什么

实现集中在 `Simulation/ConstructionSimulation.cs`，状态与存档兼容分别在 `Models.cs`、`Persistence.cs`。本轮采用下面的原型参数，而不是宣称所有数值已与 1.13.11 一致：

| 能力 | 本轮实现与边界 |
|---|---|
| 国家施工资源 | 全国统一分配，基础固定 10 点/周；实际营建产能取决于在岗人数和生产方式 |
| 排队 | 下单不预付整笔造价；政府队列支持排序、暂停和取消；500 项是技术保护上限 |
| 单项目速度 | 固定上限 10 点/周；尚未连接原作城市化等科技链 |
| 营建部门 | 可以建设；提供真实岗位；支持木架 2 点和铁架 5 点两种方式 |
| 生产方式 | 铁架暂由现有“机械工具”研究解锁；原作对应的城市规划科技尚不存在 |
| 商品配方 | 使用当前六商品模型中的木材、铁、工具；没有布料，配方和工资经过独立调参 |
| 预算 | 按实际施工利用率扣材料，按在岗人数付工资；全部暂停时仍支付工资 |
| 缺料 | 按生产方式分别核算材料与付费营建产能，共用库存不能重复使用；缺铁不会连不需要铁的木架部门一起停工；免费基础能力仍可使用 |
| 地区效率 | 当前固定为 1.0；未使用真实地形、市场接入或地方效率加成 |
| 工程地点 | 继续使用城市作为经济和建造目标；没有假称已实现原作州级经济结构 |
| 完工 | 对目标城市增加相应产业或营建部门等级，再刷新就业与全国汇总 |
| 旧存档 | 旧预付款项目按进度比例迁移，保留已支付标记；迁移不凭空赠送新营建部门 |

当前木架配方为每满员级每周 14 木材和 1 工具、工资 14；铁架为 10 木材、8 铁、3 工具、工资 21。工程需求分别为农场 60、伐木场 80、煤矿与铁矿各 120、工具厂 160、纺织厂 140、营建部门 80 点。这是适配原型经济尺度的独立数值，不能与原作的商品单位、成本或历史统计混用。

## 尚未实现的完整系统

- 投资池、私人自动投资、经济法的政府/私人能力分配。
- 建筑等级所有权、分红、金融区与庄园、私有化、外国投资权。
- 精确州/省经济单位，以及城市仅作为州内视觉锚点的分离。
- 劳工资质、完整职业转换、基础设施瓶颈、地方价格和市场接入。
- GDP 决定的免费建造能力、完整施工科技、钢架和电焊材料链。
- 与原作一致的市场买卖订单、短缺惩罚、工资竞争和财政债务边界。本轮仍沿用原型的库存经济；“持续扣材料”并不等于已经完成 Victoria 3 市场模拟。

这次应验收的是：旧的购买倒计时已经被全国施工系统替换，预算、材料、营建部门、优先级和工期能够相互影响。只有把上面的依赖系统逐项实现并测试，才可以进一步提高与目标版本的机制一致性。

## 针对这次改动的验证要求

1. 排队本身不扣整笔工程费或储备材料。
2. 相同全国产能下，把相同项目分到更多城市，不会凭城市数量增加总进度。
3. 单项目不突破上限，完成当日的剩余能力可以用于后项。
4. 暂停后进度与材料用量停止，部门工资继续结算；恢复保留原进度。
5. 排序能改变后续能力分配；取消不产生材料退款或额外收益。
6. 缺料降低付费产能，材料库存不会变负；免费能力仍可建设。
7. 营建部门完工和生产方式切换，能够改变真实全国施工能力及成本。
8. 保存读取保留顺序、暂停、进度、部门等级与生产方式；旧版预付款项目不能二次收取相同材料费。
9. 混用生产方式时，某一种材料短缺不会停止无需该材料的部门；当队列需求已经超过实际可供能力，添加纯等待项目不应再提高健康部门的产出。

实际测试结果以本次 `TEST-REPORT.md` 为准；这里列的是机制验收标准，不是自动宣称所有检查已经通过。
