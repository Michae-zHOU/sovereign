# Sovereign 与《Victoria 3》的实质机制对照

审计日期：2026-09-19。目标版本：**Victoria 3 1.13.11**。主任务已核验本机 `Victoria3.exe` 的 FileVersion 为 1.13.11；本研究独立核验到官方 2026-08-19 的同版本发布公告。DLC 启用列表、模组、游戏规则与原作存档尚未作为逐项验收基线确认。

本文件检查的是**开始本轮任务时的 Sovereign 0.9 模拟结构**。主任务正在实现的 0.10 不在本次静态审计结果内；完成后应逐项更新“状态”和回归证据，不得仅凭版本号标记通过。本文件只新增文档，没有修改模拟代码。

结论：0.9 已有建设队列、地区/城市人口、行业投入产出与国家操作，但经济仍以全国实物库存为中心，人口和政治主要是汇总数值。它与 1.13.11 的订单市场、分组人口、建筑经营、所有权、利益集团和立法过程仍有结构性差距。**0.10 最有价值的工作是打通“建筑生产方式 → 职业与工资 → 人口购买力 → 地区价格 → 所有者收益 → 政治支持”的闭环。** 增加界面入口或地图装饰不能替代这些机制。

## 2. 当前代码的关键证据

以下是审计时的符号与行为；后续重构可能改变行号，故以符号定位。

| 代码位置 | 0.9 中观察到的实现 | 影响 |
|---|---|---|
| `Models.cs`：`CountryState.Goods/Prices` | 全国共享库存和价格；没有地区买卖单、市场区域或人口账户 | 所有城市在同一全国仓库依次取货，所在地供需不形成价格。 |
| `SimulationEngine.TickEconomy` | 使用库存/目标库存决定利用率和价格，按行业、城市顺序消耗实物投入 | 行业迭代顺序影响谁先得到原料；这不是原作开放订单模型。 |
| `TickEconomy`：`pretaxWages`、`HouseholdNeed` | 工资由全国增加值的固定 76% 推算；所有人口消费相同固定比例的粮、木、衣 | 不能形成工人、农民、地主、资本家的收入、需求和政治分化。 |
| `RegionalSimulation.RefreshCityWorkforce` | 城市人口 45% 固定为劳动力、22% 固定为 artisans，每产业等级统一 2,500 岗位 | 没有职业资格、工资竞争、建筑招工和分组失业。 |
| `TickDemographics` | 按同一增长率改变乡村/城市人口，月度按机会由本地区乡村迁入城市 | 文化、宗教、身份、跨地区/跨国迁移与食物安全未建模。 |
| `EnactReform` | 扣固定金额后立即加入改革集合 | IG 反对、合法性、立法阶段、妥协与机构投入均不存在。 |
| `TradeWithExternalMarket` | 对一个有限外部仓库，以基础价乘 1.1/0.9 从国库直接进出口 | 贸易中心利润、世界市场机会、当地价格、关税/补贴和私人所有权未实现。 |
| `ConstructionSimulation` | 有建造点、建筑配方、工资、项目暂停/重排；仅国家队列，原料仍扣库存 | 是可保留的交互基础；不能据此认定自主投资与原作生产方式已完成。 |
| `Diplomacy` | 关系、冷却、贸易协定及 `MobilizedAgainst` 标记；明确无战斗与割地 | 缺外交博弈、战争实体、部队、前线、补给和和平条件。 |
| `Catalog`、`HistoricalEvents` | 6 种商品、6 种产业、3 改革、3 科技；战役到 1846；5 类硬编码事件 | 尚非 1836–1936 世界内容与科技覆盖。 |

主要文件：[Models.cs](Simulation/Models.cs)、[SimulationEngine.cs](Simulation/SimulationEngine.cs)、[RegionalSimulation.cs](Simulation/RegionalSimulation.cs)、[ConstructionSimulation.cs](Simulation/ConstructionSimulation.cs)、[Catalog.cs](Simulation/Catalog.cs)、[HistoricalEvents.cs](Simulation/HistoricalEvents.cs)。

## 5. 0.10建议交付次序与判定方法

1. **先确定结算数据流。** 一期中先采集全地区建筑/人口/政府订单，再解析市场与当地价格，再结算经营、工资、需求、财富和政治。避免先执行国家/城市者优先消耗全局货物；经济结算的单元应有固定含义和单位。
2. **落实Pop与建筑账户。** 最少纳入农民、劳工、技术工人、官僚/学者、地主、资本家等代表职业；农业和未工业化人口也要进入经济。初始数值可为估算，但不能被标为历史普查。
3. **落实PM与市场。** 扩充原料链和当地订单；科技解锁真实配方变化；先实现可验证的价格方向/边界、供需解释、就业与利润反馈。未核验的完整价格/MAPI系数保留可配置并标注。
4. **落实IG与立法。** 支持度来自Pop政治力量，改革由IG支持/反对驱动阶段进展；成功后启用法律。可以先限制法律数量，但所有出现的可操作法律必须连到实际系统。
5. **立即准备所有权与投资接入。** 如果本批不能完成自主投资，不将国库建设包装为“私人投资”；把它列为明确未完成项，数据结构不要继续假设一切建筑由国家支付和拥有。
6. **用场景验收交互链。** 同一个税率变化、PM切换、粮价上涨、地主收益下降应在账单、需求、利润、财富、IG势力和改革支持里留下相互一致的结果。

最低回归场景：

- 同需求下增加一种商品供给，市场价下降；同一期国家/城市迭代顺序变化不改变实质结果。
- 分别设置高/低接入和高/低MAPI四组合；对比目标原作当地价，避免把接入与MAPI误当同一变量。
- 原料缺口只影响依赖该输入的方法；换技术配方会改变职业与成本，不给所有行业同时凭空加成。
- 同城市资本家和劳工净收入不同，消费包/财富变化不同；征税能指出谁承担负担。
- 乡村人口转入工业后，自给生产、地主收益、工业工资和IG支持同时发生变化。
- 改革尚未通过时不提前套用所有效果；保存/读取保留本轮进度、支持和下一次结算时点。
- 0库存旧存档迁移后，订单市场仍正常运行；不能因兼容字段为0而关闭所有生产。

“基本一样”的验收应使用**相同版本、相同DLC、相同游戏规则的原作场景和可观察操作结果**。本轮尚未完成逐场景双边实测，不能给出一个虚构的完成百分比。
